# FlowDNS 1.0.2-r1

本次优化启停和节点变更后的出口恢复，保留 1.0.x 两种模式、默认策略和数据路径。服务和 LuCI 同步升级到 1.0.2-r1，可选私有核心仍为 1.12.25-r1。已有 1.0.0 / 1.0.1 归档和标签不变。

## 改进和实际边界

- 核心接管后立即验证代理及加密 DNS。启动前 90 秒的依赖重试间隔最多 4 秒；持续故障仍退避，避免无休止高频启动。
- 健康探测在独立后台任务执行，监管可继续发现节点变更。恢复期一次探测结束约 2 秒后重试；单次 DoH 探测仍可能用到 3 秒，DoT 及多组探测会更久，节点插件自身启动时间也计入实际恢复时间。
- 配置事件唤醒验证；内容修订也能识别相同大小、相同 mtime 的配置变化。修订摘要仅用于变化检测，不是密码学完整性证明，也不向界面输出节点凭据。
- SOCKS 模式节点变化不重启 FlowDNS；透明模式需校验并重载独立 Xray，会中断旧连接。FlowDNS 不替代 SSR/PassWall 的节点选择和插件重启，也不自动选择其它节点。
- 恢复期首次失败就验证加密备用；稳态连续两次失败后评估切换。仅在备用成功时切换，逃离失效 DNS 不再受旧冷却期阻塞；主 DNS 切回仍有连续成功和保持时间。
- 监听、接管和“国外出口验证”分别显示。探测结果绑定核心 PID 和配置修订，节点变化期间的旧探测不能覆盖新状态。验证加密 DNS 经 SOCKS 成功仍不代表所有网站、游戏、UDP 或视频吞吐通过。
- 用户任务可排在正在执行的健康探测锁后面，后台不再抢着插入新探测。不删除内核锁，不同时启动两个配置事务。LuCI 升至 v2 路径，避免旧缓存模块混入。

## 安装包选择

| 目标 | 服务包 | 界面 | 核心 |
| --- | --- | --- | --- |
| BPi-R3 Mini / MTK | `flowdns_1.0.2-r1_aarch64_cortex-a53.ipk` | `luci-app-flowdns_1.0.2-r1_all.ipk` | 现场透明模式；保留已验证的系统 1.12.22 |
| NanoPi R5S / RK3568 | `flowdns_1.0.2-r1_aarch64_generic.ipk` | 同上 | 现场 SOCKS 模式；保留私有 1.12.25；可选包 `flowdns-core_1.12.25-r1_aarch64_generic.ipk` |

仍需匹配固件 ABI、firewall4/nftables 和内核模块。不要给其它 CPU 安装上述包或仅修改 Architecture。x86_64 / ARM32 用匹配 SDK 重编，按 [PORTING.md](PORTING.md) 验收。私有核心不覆盖共享系统 sing-box。

升级前保存原服务/UI 包与配置。若旧包被 hold，先对 `flowdns` 和 `luci-app-flowdns` 解除 hold，再安装对应服务/UI 两包；无需为本次恢复优化解锁或升级核心。升级保持已有模式、规则和节点，首次安装仍默认关闭。测试通过后可重新 hold 两包。手动应急/降级步骤见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。

## 源码与验收

发行包含两架构服务、一份通用界面、可选 generic 私有核心、完整源码、manifest 和 SHA256SUMS。源码附 dnsmasq 2.93、固定 sing-box 上游源码和私有核心 vendor 依赖，保留各自许可证；不包含用户配置、SSH 身份或原始浏览日志。

验证范围与部署结果见 [2026-10-24 恢复优化记录](diagnostics/2026-10-24-1.0.2-recovery.md)。完整隔离回归覆盖两种模式、Reality/Vision、IPv4/IPv6 TCP/UDP、128 次并发 DNS 和 DNS-only 更新时同一下载连接保持。现场恢复用时是当次节点和时段的观测，不是任意线路的承诺；切模式后的客户端缓存仍需清理。

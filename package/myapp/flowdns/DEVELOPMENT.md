## 性能结论应如何表述

SOCKS 是本机一层额外转发，但本次固定目标 5MB 三轮测试中，透明约 11.6–12Mbps，SOCKS 约 10–13Mbps，重叠明显。0.4 后用户视频体验改善，不能仅凭前后截图认定全由 SOCKS 开销、BBR、ISP UDP QoS 或某个 CDN 引起。新 QUIC 策略和 DNS 事务都主要优化透明模式，用户后来 SOCKS 同样很快，更说明必须控制节点、时段、协议、CDN、Wi-Fi、客户端缓存再归因。

用户截图 21,998→42,967Kbps、缓冲 37.65→75.83 秒，属于用户真实客户端反馈；受控限速 20MB 测试用于验证不断流，不代表最大带宽。当前宽带 UDP QoS 尚无负载对照证据。

## 2026-10-24 恢复优化的实现教训

将“启动成功”拆为配置/监听/接管和出口验证两层：出口暂时失败不回滚已经可用的国内服务，也不能显示国外已可用。每次探测记录核心 PID 与配置修订，结束时再次比对；节点变化时丢弃旧结果。后台化探测后，用户操作必须有明确排队语义，不能再让健康维护阻塞整个监管循环，也不能通过抢锁制造两个事务。

修订检测在宿主机正常不代表目标 Lua 正常。首轮 `%08x` 格式化较大无符号值在目标 Lua 5.1 的 32 位整数上不适用，改用不依赖 lua_Integer 宽度的十进制格式，并核对两架构包内字节。变化摘要不承担密码学用途。测试还补充相同大小/时间戳的内容变化和真正内核锁下的用户任务等待，避免只验证理想时序。

同日下载排查也说明“慢”不能一概归因于 SOCKS：游戏样本大量是很小的 Range 请求，直接链路和独立 SOCKS 小请求吞吐接近；同一出口大块传输更快，尚不能据此定位完整游戏下载器瓶颈。Linux Mint 官方远端源约 0.25–0.37 MB/s，镜像对照约 1.95–3.4 MB/s；用户授权更换四行官方主源/基础源后，索引刷新约 39.4 MB / 7 秒。保留安全源、第三方源和签名校验。此为客户端源选择处理，没有改 FlowDNS 路由；私有访问日志与节点信息不进入公开仓库。

## 必须保留的维护约束

1. 不以“进程存在”代替所属进程监听、实际 DNS 应答、nft/路由接管和 LAN 客户端访问。
2. 运行快照与已保存配置分开显示；失败候选不应停止现有服务，已保存 UCI 与恢复快照可能不同。
3. 规则、DNS、Xray、前端、nft 必须按同一候选策略生成；仅严格识别的纯 DNS 变化允许局部更新。
4. 不继承插件的 DNS/防火墙接管，不清空其他服务的路由表，不使用 `nft flush ruleset` 修复。
5. 并发测试使用正式执行模式和真实库/内核，不用简化 stub 或 no-daemon 代替关键 fork 路径。
6. 本地注入回退验证、目标安装、用户视频和完整公网 IPv6 各自记录，不互相代替。
7. 诊断输出避免节点凭据；Xray JSON、完整 UCI、运行快照与 SSH 私钥不能进入源码归档。
8. 远程测试前保存可恢复包/配置，准备独立超时恢复；网络失效先回退并停止测试，不连续叠加试验。

## 代码定位

- `src/core.lua`：配置校验、SOCKS 策略、sing-box/nft 生成、路由归属。
- `src/transparent.lua`：SSR 生成适配、Xray、真实 IP 前端与 nft 集合、QUIC、DNS-only 分类。
- `src/system.lua`：实际系统检查、锁、进程/监听及性能采样。
- `root/usr/libexec/flowdns`：候选、事务、规则、健康、诊断与任务队列。
- `root/usr/libexec/flowdns-engine`：业务子进程监管和 DNS 后端事务执行。
- `root/usr/libexec/flowdns-run`：启动等待、健康维护、规则刷新、恢复与日志轮转。
- `root/etc/init.d/flowdns`：procd、自启动和接口事件。
- `../luci-app-flowdns`：LuCI 状态/设置、RPC 白名单及 ACL。
- `tests`：策略、真实库、正式引擎、本地 TLS/SOCKS、隔离 LAN、发布包检查。

## 正式发布前发现的测试夹具问题

首轮1.0完整回归普通VLESS通过，Reality轮的128次混合DNS出现单次UDP查询超时，单项复测也出现；当时未修改生产数据路径或放宽超时。检查本地HTTPS测试服务器发现TLS握手在accept主线程串行执行，Reality探测与DoH共用服务会相互排队。新增独立负对照：先连接一个不发ClientHello的客户端，再发正常TLS请求，旧夹具正常请求超时。修复为工作线程内握手、有界握手时间与足够接收队列；新负对照正常请求完成，原有128并发/6秒DNS超时保持。失败日志额外保留DNS后端尾部。这个独立测试证明夹具存在阻塞缺陷；最初单个UDP丢失没有逐包捕获，不能声称其所有成因已穷尽。修复后完整回归结果以正式发布记录为准。
